Вход 1. Требования R1, версия 21.11.2026.
Консольная программа проверяет одну вымышленную строку за запуск и выводит OK либо коды нарушений. Пароли не сохраняются и не отправляются в сеть. GUI, базы данных, регистрации и оценки криптостойкости нет.
R01: src/PasswordValidator.java без package, Java 17, стандартная библиотека, консольный запуск.
R02: читать первую строку целиком, включая пробелы, без перевода строки.
R03: длина 8–16 включительно по String.length(), иначе LEN.
R04: минимум одна заглавная латинская буква A–Z, иначе UPPER.
R05: минимум одна цифра 0–9, иначе DIGIT.
R06: допустимы A–Z, a–z, 0–9, иначе CHAR. Для пустого ввода CHAR не выводится.
R07: все правила выполнены — ровно одна строка OK.
R08: все нарушения выводить без повторов по одному в строке в порядке LEN, UPPER, DIGIT, CHAR.
R09: пустая строка или EOF перед первой строкой — LEN, UPPER, DIGIT без аварийного завершения.
R10: следующие строки игнорировать. Не печатать приглашения, пояснения или проверяемое значение.
Критерии: сборка javac --release 17; 13 различных сценариев, минимум 3 граничных; связь R01–R10 с ожидаемыми и фактическими результатами; 50–150 непустых некомментированных строк программы; тесты отдельно; сохранение фактического запроса, журнала, условного промпта, разбора хотя бы одного реального или явно учебного дефекта; акт приёмки с решением, свидетельствами и ограничениями. Требования задним числом не подгоняются.

Вход 2. Исходная карта P1.
A: уточнить требования. Вход R1, выход замечания и вопросы. КТ1: непротиворечивость R1.
B: спроектировать сценарии. Вход подтверждённая R1, выход T01–T13 с ожидаемым выводом. КТ2: покрытие и границы.
C: подготовить код. Вход R1 и сценарии, выход Java-файл и команды. Проверка: компиляция и просмотр ограничений.
D: разобрать проверки. Вход код, сценарии, реальные запуски, выход матрица и расхождения. КТ3: ожидание сравнивается с фактом.
E (условный): исправить дефект. Вход карточка дефекта и нужный исходник, выход минимальная правка. Проверка: повтор неуспешного и связанных сценариев.
F: принять результат. Вход финальный код и проверки, выход акт и ограничения. КТ4: полный итоговый прогон.
Переходы: A → B → C → D → F. При дефекте D → E → D. Перед F нужен полный прогон. При нехватке входа, противоречии или исчерпанном лимите исправлений — остановка и решение человека. Для КТ1–КТ4 проверяющий — владелец проекта, для каждой нужны конкретное свидетельство, статус и решение.
