# Независимый аудит требований R1 и карты процесса P1

Проверены шаги A–F, контрольные точки КТ1–КТ4, передача результатов между шагами, маршруты возврата и условия остановки. Основание — три файла на коммите `d4e04d41e1ac4a823c6313a1b64b3ea38ffb0896`. Аудит выполнен по текстам документов. Для подтверждения компиляции и результатов запусков нужны соответствующие журналы. [Требования R1](https://github.com/ariverix/prmt-final-project-skf/blob/d4e04d41e1ac4a823c6313a1b64b3ea38ffb0896/docs/requirements.md) · [Карта P1](https://github.com/ariverix/prmt-final-project-skf/blob/d4e04d41e1ac4a823c6313a1b64b3ea38ffb0896/docs/process.md) · [Шаблон аудита](https://github.com/ariverix/prmt-final-project-skf/blob/d4e04d41e1ac4a823c6313a1b64b3ea38ffb0896/prompts/B_audit_separate_chat_NOT_SENT.md)

Сервис — Codex в ChatGPT Work Mode. Среда указывает семейство GPT‑6. Точный идентификатор модели не раскрывается.

Правила R03–R10 согласуются для явно описанных случаев. В частности, пустая строка и EOF до первой строки дают `LEN`, `UPPER`, `DIGIT` в этом порядке, а длина однозначно определяется через `String.length()`. Основные пробелы относятся к воспроизводимости проверок, передаче свидетельств и решениям при сбоях.
