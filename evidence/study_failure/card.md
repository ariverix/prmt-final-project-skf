# D01 Проверка нижней границы

Дефект намеренно внесён в отдельную учебную копию. В истории проекта он обозначен как учебный и в финальную программу не включён.

| Поле | Данные |
| --- | --- |
| Объект | `buggy/PasswordValidator.java`, хеш в [before.txt](before.txt) |
| Вход и правило | T01, `Abcdefg1` и перевод строки, 8 элементов Java-строки, R03 и итоговое поведение R07/R08 |
| Ожидание и факт | Ожидалось `OK`, получен `LEN`. Код выхода программы 0. Раннер вернул 1 |
| Причина | `password.length() > MIN_LENGTH` исключает 8, хотя R03 включает нижнюю границу |
| Область влияния | Точный вывод T01, T05, T06, T07, T10 и T11: длина первой строки во всех случаях 8. В T05/T06/T07/T10 появляется лишний LEN, в T01 и T11 вместо OK выводится LEN. Остальные 8 сценариев дефектной версии прошли |
| Возврат | D обнаруживает расхождение и передаёт карточку в E. В E восстановлен оператор `>=`, затем новая сборка C и повторы D. T01–T04 контролируют обе границы, оставшийся набор проверяет отсутствие регрессии |
| Попытки | H02 исторически зафиксировал внесение и восстановление оператора, 0 запросов на исправление. В итоговой сессии Codex повторно собрал обе сохранённые версии и сравнил их. Исправленная копия побайтно совпадает с финальным исходником |
| Повтор и решение | До 8/14, после 14/14 на локальном JDK 21 с целевой Java 17. GitHub Actions на Temurin 17 подтвердил `LEN` до, `OK` после и 14/14 итоговых. Техническое решение: D01 закрыт |
